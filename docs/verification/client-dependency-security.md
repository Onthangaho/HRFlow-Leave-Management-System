# Client dependency security verification

On 6 October 2026, `fix/client-dependency-security` was created from fetched origin/main
at adc5df7 (merged HR employee management PR #65). The working tree was clean.

## Fresh audit and focused changes

Full `npm audit --json` reported two high-severity affected packages (13 individual
advisories: eight high and five moderate); npm aggregates severity per package.

- Production: direct `hrflow-client -> axios@1.19.0`. The client bundles Axios and uses
  browser JSON requests. The package includes both browser and Node security findings;
  Node-only paths are absent from this app, but this does not prove all prototype
  pollution gadgets unreachable. Compatible patched version: 1.20.0.
- Development/build: `hrflow-client -> postcss@8.5.26 -> source-map-js@1.2.1`, and
  `hrflow-client -> @tailwindcss/postcss@4.3.3 -> @tailwindcss/node@4.3.3 -> source-map-js@1.2.1`.
  Indexed source-map section offsets can cause Node event-loop denial of service
  (GHSA-68fv-2mgg-jv7q). Compatible patched version: 1.2.2, within both parents' ^1.2.1 range.

Axios high findings: data-URL ReDoS (GHSA-c29m-xwm3-cm6r), proxy ReDoS
(GHSA-mghh-pgcx-3jjj), form options pollution (GHSA-x97p-jq2g-jp4f), HTTP/2 control bypass
(GHSA-3pq3-5fj3-cg6v), HTTP/2 unhandled error (GHSA-542g-h47m-68v8), Node socket gadget
(GHSA-m8m8-qj5v-23w3), and fetch redirect guard bypass (GHSA-r4gj-5m52-g5wh).
Moderate findings: fetch options gadget (GHSA-vh66-26gq-q6x8), inherited default method
(GHSA-9fr6-4gfg-395g), inherited headers (GHSA-j8rh-479h-cp32), FormData headers
(GHSA-4hqw-qxg8-jxx2), and NO_PROXY CIDR handling (GHSA-44g4-m2mj-wpvx).
The [prior investigation](../adr/0003-hr-employee-management.md#dependency-advisory-investigation-6-october-2026)
contains individual advisory links; a fresh audit confirmed these same findings before this update.

The manifest raises Axios from ^1.19.0 to ^1.20.0; the lockfile selects Axios 1.20.0
and source-map-js 1.2.2. No other package versions, graph entries, overrides, or application
source changed. Unrelated peer metadata generated by npm was removed before a clean install.
No forced audit fix or broad upgrade was used. All currently reported findings are resolved.

## Actual verification

- `npm ci`: installed 92 packages, audited 93; found 0 vulnerabilities.
- `npm run build`: passed, 225 modules, production JavaScript 450.12 kB (138.22 kB gzip).
- `npm run lint`: exit 0; only the existing useAuth.tsx:184 Fast Refresh export warning.
- Final `npm audit --json`: exit 0, zero findings in every severity category.
- Final `npm audit --omit=dev --json`: exit 0, zero production findings.
- Baseline lockfile audit reproduced exit 1/two high packages in an isolated temporary
  directory; before/after audit JSON and browser evidence remain outside the repository.
- `dotnet build HRFlow.sln`: passed with zero warnings/errors for the disposable API.
- `git diff --check`: passed. Both instruction files remain identical.

Real isolated Chromium used the upgraded client against a fresh disposable Development
SQLite database. Login/logout passed for Employee, Manager, and HR. Personal balances/history
loaded two Pending requests. Removing Authorization from one outgoing request caused a real
API 401, successful refresh 200, and successful Axios retry, without a mocked response.
After account switches, the manager's personal history remained empty rather than displaying
the employee's cached records. The manager queue loaded two direct-report requests and approval
returned 204/refreshed the queue. Personal history showed the approval and cancelled the other
request via 204. HR monitoring loaded both Pending records without decision controls and later
refetched its empty state.

HR directory creation and edit passed without a document reload. Existing department,
manager, and combined roles were preserved; the new login email worked after the profile edit.
No browser page errors occurred. An independent DbContext confirmed the edited profile,
Identity email/login, roles, manager, version, Approved/Cancelled statuses and one matching
terminal audit per leave request. The temporary servers were stopped after verification.

## Limits

The connected browser service had no available browser; isolated headless Chromium was used.
Other browser engines, production deployment/load, every refresh/error/cancellation race,
and vulnerability exploit reproductions were not checked. Audit results describe the registry
at verification time, not a guarantee against future advisories. Existing databases were
preserved. No repository automated test files, backend/schema changes, commit, push, PR,
or issue changes are part of this task. Issue #23 has not resumed.
